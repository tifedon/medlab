02  Executive Summary
Aurevia IMRES is intended to be a multidisciplinary medical research and education institute with a strong digital publishing, evidence review, visualization and scientific communication capability. The website is not meant to be a brochure site. It is intended to function as the public-facing knowledge infrastructure of the institute.
The central idea is to bring research, people, scientific divisions, publications, books, education, evidence review and medical visualization into one coherent institutional ecosystem. A researcher should be able to have a professional profile connected to current and completed research, publications and books. A research project should link to its investigators, division, reports and resulting publications. A book should link to its editors and contributors, the relevant division, related research and purchase or distribution channels.
The first technical implementation is a multi-page Next.js application using TypeScript, Tailwind CSS, the App Router and structured local data files. The architecture has been deliberately designed so that local content can later be replaced by a content management system or database without rebuilding the entire front end.

What Makes the Concept Different
It combines medical research, education, publishing, evidence integrity and scientific visualization under one institutional identity.
It treats books and scholarly publications as first-class institutional outputs, not as an afterthought.
It creates durable public profiles for experts and connects those profiles to the work they actually contribute to.
It distinguishes current, upcoming, in-progress, completed and published work so the website can show institutional activity over time.
It is designed to scale from static demonstration content to a real editorial and research content system.

Recommended Authorship and Imprint Model
Recommended modelUse the real doctors, researchers, editors or qualified subject experts as authors or editors. Use Aurevia IMRES as the institutional affiliation and Aurevia IMRES Press as the publisher/imprint. Use Aurevia IMRES as a corporate author mainly for official institutional reports, standards, consensus documents, evidence summaries and similar works.

Not every contributor must be a physician. Contributors should be qualified for the material they handle. Depending on the title, contributors can include respiratory therapists, nurses, pharmacists, biomedical scientists, physiologists, statisticians, medical illustrators, methodologists and medical editors. Clinically sensitive material should receive appropriate clinical review.

22  Design System and User Experience
The visual direction should communicate academic credibility and scientific seriousness. It should not look like a generic SaaS landing page or a generic hospital template.
Design Principles
Professional academic typography and strong information hierarchy.
Generous whitespace and restrained use of color.
Subtle biomedical or scientific visual language rather than decorative technology gradients.
Cards and grids used for information structure, not as the entire visual identity.
Clear status badges for research, projects and books.
Consistent detail-page templates so users know where to find abstracts, contributors, dates, methods and related content.
Responsive mega-menu on desktop and usable mobile navigation on smaller screens.
Visual Content Policy
Prefer authentic institutional photography, original illustrations, scientific diagrams and carefully licensed imagery. Avoid implying specific hospitals, patient relationships or facilities through unrelated stock photos. Medical illustration should be treated as an institutional capability, not merely decoration.

24  Accessibility, Privacy and Security
Accessibility Target
The site should aim for WCAG 2.2 AA level practices: semantic headings, keyboard navigation, visible focus states, adequate contrast, form labels, useful link text, alt text for informative images and accessible tables. Automated tests are useful, but manual keyboard and screen-reader checks are still needed.
Privacy and Data Handling
Do not collect patient medical data through ordinary contact forms.
Collect only the minimum personal information needed for inquiries, applications or collaboration.
Publish a privacy policy before forms and analytics are enabled.
Define data retention and access rules for contact submissions.
If newsletters or email marketing are added, use consent-based subscription practices and appropriate unsubscribe controls.
Security Basics
HTTPS through the hosting platform.
Environment variables for secret keys, never hardcoded credentials.
Spam and abuse protection on public forms.
Dependency updates and security scanning.
Role-based access if a CMS or admin area is later introduced.
Backups and export procedures for production content.

26  Deployment and Domain
The planned deployment path is a Git-based workflow to Vercel, with aimres.site configured as the custom domain. The current project is configured for static export, which is suitable for an early content-driven version.
Phase 1 Deployment Flow
1.  Install dependencies on a network-enabled development machine.
2.  Run type checking, linting, route tests and a production build.
3.  Push the repository to GitHub, GitLab or Bitbucket.
4.  Import the repository into Vercel.
5.  Deploy and test representative routes, including dynamic records.
6.  Add aimres.site under Vercel domain settings.
7.  Copy the required DNS records into the domain registrar.
8.  Wait for DNS and TLS verification.
9.  Set the preferred canonical domain and retest the site.
Static export caveatA fully static export cannot itself process contact forms or authenticated administration. Those features require an external form service, serverless/API functions, or a future backend/CMS. If the application moves beyond static hosting, the deployment configuration should be updated accordingly.

Appendix B: Partner Summary
In practical terms, Aurevia IMRES is being built as three things at once: an institution, a digital knowledge platform and a publishing ecosystem. The website should make those three layers reinforce each other.
InstitutionA multidisciplinary structure for research, clinical science, dentistry, nursing and allied health, pharmacology, biomedical science, evidence integrity, medical illustration and publishing.

PlatformA searchable multi-page application where people, research, projects, publications, books, education and insights are connected through reusable structured data.

Publishing ecosystemAurevia IMRES Press can publish books and institutional works, while named qualified authors, editors and contributors receive appropriate credit and PublishDrive can distribute approved titles externally.

The strongest long-term version of the project is not one that appears large immediately. It is one that becomes increasingly authoritative because every profile, research record, publication, book and claim is structured, verified, linked and governed consistently.
